Bootsharp C# WASM - worker thread pool

A small JS-side pool manages a capped set of dedicated Web Workers, each booting its own Bootsharp .NET runtime instance. Workers are spawned lazily, on demand, as jobs arrive - not all up front - since each one carries a fair amount of memory. Jobs beyond the cap queue up and are dispatched the moment a worker frees. Optionally, a total memory budget stops new workers from spawning once the pool is likely to blow it, and a per-worker recycle limit terminates and reboots any worker whose self-reported WASM heap creeps past it (WASM linear memory only grows, so that's the only way to reclaim it). Every job is one synchronous RunJob(...) call into C# inside its worker - the main thread stays responsive throughout, as shown by the heartbeat below.

Part-way through, C# may need something only the user can supply. It calls a synchronous JS import, AskUser(prompt), any number of times per job. The worker can't receive a postMessage while it's stuck inside C#, so it parks on Atomics.wait over a SharedArrayBuffer; the UI writes the answer into that shared memory and wakes it with Atomics.notify. Questions from different workers queue up below and can be answered in any order. Requires cross-origin isolation (COOP/COEP headers, see serve.json).
